# Заметки по проекту «Сыграем»

## 1. Сделано
Отмена игры по секретному коду — готово, протестировано (создание →
показ кода → неверный код → верный код → игра удаляется), закоммичено
и запушено (`18d2d89`).

## 2. Дальше по плану
Вход через Google (Supabase Auth). Один тип аккаунта для всех —
организатором становится тот, кто создал игру (не отдельная роль).

## 3. После логина обязательно переписать RLS-политики
Сейчас `update` и создание — `using (true)` для всех, то есть в теории
любой может отредактировать любую игру напрямую через API. Пока это
терпимо (нет логина, спасает только код отмены на delete). После входа
через Google — политики должны проверять `auth.uid() = owner_id`, чтобы
редактировать/удалять мог только владелец. Нужно будет добавить колонку
`owner_id` в `games` и связать её с юзером из Supabase Auth.

## 4. Мелочь
Удалить тестовую строку `id=2` ("curl test") в Table Editor — у неё
фиктивный хеш кода, её нельзя отменить через приложение.

## 5. Урок на будущее
Если SQL Editor пишет "Success", это не значит, что объект реально
создался — если несколько операторов идут в одном запросе, ошибка в
одном может откатить всё остальное молча. Правило:
- выполнять по одному блоку за раз (таблица / функция / grant отдельно);
- после каждого — проверять факт через `information_schema.columns`
  (для колонок/таблиц) или `select proname from pg_proc where proname = '...'`
  (для функций), а не полагаться на текст "Success".
